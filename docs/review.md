# UF2 核心边界独立审查

于 2026-10-06 对照 [Microsoft 官方 UF2 规范](https://microsoft.github.io/uf2/)完成审查。

## 结论

在已审查的核心实现中，未发现阻碍交付的正确性缺陷。独立测试文件 `review_test.mbt` 的 **15 项测试在 JavaScript 和 Wasm GC 目标上均通过**，所用 MoonBit 版本为 `moon 0.1.20260920 (914d7da 2026-09-20)`。

本次工作仅涵盖限定范围内的源码审查与回归测试，不构成安全认证，也未进行硬件刷写测试。适配器行为、命令行工具的文件系统处理和第三方固件解析器不在本次审查范围内。

## 规范与支持范围

规范定义了 512 字节的块、三个魔数、无符号小端序头部字段、476 字节的数据区，并要求主闪存载荷及目标地址按 4 字节对齐。规范还描述了乱序、重复写入、可选的芯片家族标识、多家族文件拼接，以及可选的文件容器、校验和与扩展功能。

MoonUF2 有意采用更严格的普通主闪存子集：逻辑镜像必须完整且非空，块总数必须一致，芯片家族设置也必须统一。遇到不支持的标志位或混合家族文件时，直接拒绝处理。面向用户的文档应持续明确这一支持范围。

## 独立自动化测试覆盖

测试直接构造原始头部，不依赖实际编码器，从而降低编码器与解码器的共同缺陷掩盖无效输入的可能性。

- 过短、空输入及未按 512 字节对齐的输入长度
- 全部三个魔数，以及错误所在物理块的索引
- 每一个不支持的单独标志位，以及支持与不支持标志位的组合
- 从 4 到 476 字节的全部 119 种有效对齐载荷长度
- 值为零、过大、未对齐、最高位为一及 UInt32 最大值的载荷长度字段
- 未对齐地址，以及恰好达到和超出 32 位地址空间的终点
- 值为零或无效的块编号；使用恶意的 `numBlocks = 0xFFFFFFFF`，验证不会据此分配等量空间
- 缺失的逻辑块索引，包括重复块抬高物理块数的情况
- 不一致的逻辑块总数、家族标识存在性混用、标识值混用、预期家族不匹配及非零保留字段
- 完全相同的逻辑重复块合并，以及地址、长度或字节内容冲突的拒绝处理
- 三个块的全部六种排列，包含重复块，并使逻辑编号顺序与地址顺序不同
- 相同地址和部分重叠，以及恰好相邻的有效边界
- 超出地址范围的 UInt64 输入，以及调用方原始段顺序的保留
- 调用方指定的 BIN 地址跨度上限，以及 16 MiB 的硬性上限
- 恰好 16 MiB、包含 32,768 个逻辑块的 UF2 生成与解码，以及多出一个物理块时的拒绝处理
- 恰好 16 MiB 的 BIN 接受处理，以及多出一个对齐字时的拒绝处理
- 生成完整载荷块和较短末块时，将所有未使用字节填零

## 源码观察

- 解码器完成长度、魔数、标志位、载荷大小、对齐、地址和编号校验后，才会切取载荷。
- 地址终点使用 UInt64 计算。允许不包含在数据范围内的终点为 `0x100000000`，拒绝更大的终点。
- 解码器仅存储实际读取的块，不会按照不可信的声明总数分配数组。索引互异、处于有效范围内且唯一块数恰好等于声明值时，即可确认完整性。
- 重叠检查针对已校验并排序的地址范围执行。恰好相邻的块有效；不同逻辑编号的块即使数据相同，也不能重叠。
- 在块总数与家族一致性检查通过后，根据逻辑地址和载荷判断重复。未使用的填充字节允许不同；测试明确记录了这一语义选择。
- 解码器与 BIN 输入、UF2 输出以及展平后的 BIN 地址跨度均有上限。这些是数据量上限，并不保证进程总内存不超过同一数值；中间数组、返回的字节缓冲区、映射表和排序操作可能需要额外内存。
- 生成稀疏 UF2 时，不会为地址空洞分配空间或静默填充。BIN 展平使用明确指定的填充字节，默认为 `0xFF`，并强制检查地址跨度上限。
